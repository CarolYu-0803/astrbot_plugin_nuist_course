# 自动登录与管理员验证码交互

2.1.0 在 AstrBot 所在机器执行无界面浏览器登录。学校的 24 小时会话期限仍由学校控制；插件通过过期后重新登录，自动生成新会话和课表文件。

## 服务器准备

在 AstrBot 实际使用的 Python 环境执行：

```bash
python -m pip install -r data/plugins/astrbot_plugin_nuist_course/requirements.txt
python -m playwright install --with-deps chromium
```

Windows 使用 `python -m playwright install chromium`；也可将 `login_browser_channel` 设为 `msedge` / `chrome`，复用本机已安装浏览器。

Docker 部署必须在运行 AstrBot 的容器内安装，不是宿主机。Linux 系统依赖安装可能需要 root，应在镜像构建阶段完成；仅安装 Python 包不会下载 Chromium。容器重建后应重新准备浏览器，或在自定义镜像中固定安装。持久化 AstrBot 的 `data` 目录，避免丢失可信设备状态。

## 配置与绑定

在 AstrBot 插件面板填写：

```json
{
  "auto_login_enabled": true,
  "login_username": "你的学号",
  "login_password": "你的统一认证密码",
  "login_code_timeout_seconds": 180,
  "login_retry_minutes": 30,
  "session_check_minutes": 60
}
```

账号密码也可放在 `NUIST_COURSE_USERNAME`、`NUIST_COURSE_PASSWORD` 环境变量中，优先于面板配置。面板中的密码会保存在 AstrBot 配置文件中；本项目不内置学校账号，不将密码写入 `session.json`。不要将配置或浏览器状态提交到公开仓库。

重载插件后，用 **AstrBot 管理员账号私聊**机器人：

```text
/绑定课表登录
/课表登录
```

绑定记录保存在插件持久化数据目录的 `login_contact.json` 中，包含私聊会话标识与发送者标识。课表仍是单学校账号，所有订阅共享同一份课表；普通课表订阅不会收到登录验证码。

## 验证过程

插件自动填写学号与密码，使用学校页面现有脚本加密并提交。需要图片验证码时只截取验证码区域，通过 AstrBot 图片消息发送。回复格式：

```text
/课表验证码 a1b2c3 图片中的字符
```

`a1b2c3` 只是示例，每次使用机器人最新提示里的编号。短信验证同样回复编号与短信数字，插件每轮登录最多自动点击一次短信发送按钮；错误或超时后不会反复发送短信。验证码不写入文件。

新设备短信验证通过后，插件会点击学校的“信任此设备”。Cookie 与浏览器本地状态保存为 `state_dir/browser_state.json`，下次启动浏览器时恢复。学校可能因 IP、设备状态或策略变化再次要求短信验证，不保证永久免短信。

每次验证默认等待 180 秒；图片验证码最多尝试三次，短信最多提交两次。验证码只接受来自绑定管理员私聊、发送者和本轮编号的回复。`/取消课表登录` 结束当前登录；`/课表登录状态` 查看进度。插件卸载或重载也会取消待回复验证。

## 续期与失败处理

- 查询、推送发现会话失效时，先尝试重新登录再生成课表；每小时的后台检查也会同步课表并在需要时发起登录。
- 同时触发的查询、后台检查或手动登录共用一次登录任务，避免并发短信或重复登录。
- 等待验证码时释放状态文件锁，不阻塞验证码命令；浏览器使用异步 Playwright，学校 HTTP 查询在后台线程进行。
- 新会话必须通过真实课表接口与校历校验，才在文件锁内更新会话、快照和浏览器状态。失败时保留旧文件，课表仍按原有有效期规则尝试缓存并明确标注。
- 登录失败后自动尝试至少间隔 `login_retry_minutes`；手动 `/课表登录` 可立即重试。学校拒绝账号密码时暂停自动尝试，管理员检查密码或账号状态后再手动恢复。
- 浏览器未安装、学校页面改版、平台图片消息不可用、滑块或其他未适配验证会给出提示，可暂时关闭自动登录并使用人工登录助手。

登录发生在部署机器，因此不再需要每天从本机复制 `session.json`、`snapshot.json`。将设备状态从本机复制到服务器也不保证免短信；首次在服务器绑定并完成验证更可靠。
