# Windows 登录助手：about:blank 处理

用户报告：使用 Chromium 和 Edge 两种登录命令，点击信息门户的“本科生教学管理系统”后都出现 `about:blank` 无标题页。

仅凭这一现象不能确定学校弹窗脚本、WebVPN 转发或浏览器策略中的哪一项导致跳转未完成。普通弹窗的本地测试没有复现相同故障，因此这里采用明确的兼容处理：**复用已登录的原标签页，直接导航到本次已核实的教务入口，再打开课表。** 不修改学校脚本，也不关闭浏览器安全检查。

## 更新

1. 先在运行旧版登录命令的 PowerShell 中按 `Ctrl+C`，结束旧登录助手。
2. 使用本插件包中的 `coursebot` 登录助手源码。保留已有 `.venv`、`config.json` 和 `state`，无需删除它们。原有浏览器登录兼容处理继续保留在插件中。
3. 在更新后的项目根目录（能看到 `coursebot` 文件夹）运行：

```powershell
.\.venv\Scripts\python.exe -m coursebot login --channel msedge
```

也可以继续使用原来的 Chromium 命令：

```powershell
.\.venv\Scripts\python.exe -m coursebot login
```

本次修改没有新增依赖，无需重新下载浏览器。在源码根目录执行上述命令会直接使用更新后的源码。如果你通过已安装的 `nuist-course` 命令运行，或从其他目录启动，应先在源码根目录重新安装：

```powershell
.\.venv\Scripts\python.exe -m pip install --no-deps .
```

## 新操作顺序

1. 浏览器打开后，正常输入学号、密码和验证码，直到看到“信息门户”。
2. **此时先回到 PowerShell 按回车，无需点击门户内的“本科生教学管理系统”。**
3. 程序在原标签页依次进入教务、我的课表、理实一体和周课表。
4. 核对页面中的当前周课表，再回到 PowerShell 按回车保存。

如果已经点出了 `about:blank`，保留原来的信息门户标签页，回到终端按回车即可。程序会选择学校门户或教务页面，不会选择空白弹窗。

如果学校再次显示登录页，窗口不会立即关闭。自行完成二次认证后按回车重试；也允许手动打开课表后继续。若学校修改 WebVPN 代理路径，需更新 `coursebot/login.py` 中的入口地址，而不是把跳转失败当成登录成功。

## 改动与验证边界

- 同标签页导航经过此前已观察到的教务与课表地址，保持同一浏览器上下文与 Cookie。
- 等待终端回车时，主线程继续处理 Playwright 事件；终端输入在独立线程读取，不在输入线程调用 Playwright。
- 失败保留窗口和会话，支持重试、手动进入课表以及关闭窗口取消。
- 本机 Chromium 回归测试构造了“点击入口只生成 about:blank”的场景，验证助手能从原门户页恢复到理实一体周课表，且会话 Cookie 保留。
- 已有页面复用、浏览器事件处理、终端不可用、窗口关闭和学校域名校验均有回归测试。
- 尚未在用户当前真实学校会话中验证本次修复；具体学校侧空白弹窗成因仍未确定。
